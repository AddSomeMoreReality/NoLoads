# Состояние движка «в одном экземпляре» (T42)

SkyrimSE.exe 1.6.1170, база Ghidra (T33–T36), 08.11.2026. Продолжение `docs/CELL_LOADING_MAP.md`, раздел 11; место игрока (`currentLocation`, `cachedWorldSpace`, регион, музыка, вода) — `docs/PLAYER_MAP.md`, раздел 10, чтения указателя игрока — T32. Рендер здесь — только глобальные состояния и их писатели; что читает проход рисования — T44 (`RENDER_VIEW_MAP.md`).

Пометки: **по коду** — проверено `asm`/`xrefs`; **предположение** — вывод без проверки в коде или в игре. Потоки: M — главный, J — задания `BSJobs`, IO — `BSTaskManagerThread`, R — рендер (T44).

Сокращения для «что ломает второй экземпляр»: **И2** — второй интерьер (подключённый, не текущий), **С2** — вторая сетка того же мира, **М2** — сетка другого мира (ворота). Классы решения: **(а)** подмена на время рамки дальней стороны, **(б)** своя копия на портал, **(в)** перехват читателей, **(г)** предел движка: нужен иной путь.

## 1. Коротко

1. **Мир Havok экстерьера один на всю игру, а не на мир.** `TESObjectCELL::GetbhkWorld` (`AE#18995`) для любой ячейки экстерьера отдаёт `*AE#400440`; его создаёт `AE#19193` (из конструктора `GridCellArray` `AE#15952`), освобождает `AE#19194`; других писателей `AE#400440` нет **по коду** (`xrefs`: 2 записи, 47 чтений в 23 функциях). Ячейки двух миров (ворота) окажутся в одном `hkpWorld`. Интерьер держит свой мир (`ExtraDataList::GetHavokWorld`) — для многих интерьеров одиночки здесь нет.
2. **«Текущее место» читают не только загрузчики.** `TES::interiorCell` (`+0xC0`) читают 92 функции; среди них проверка видимости `TES::Pick` (`AE#13371`: интерьер или центральная ячейка сетки → `AE#18997`, 11 вызывающих: `Actor::CalculateLOS`, `RequestLOS`, LOS игрока), `TES::GetCell(pos)` (`AE#13322`, 8), «позиция в загруженной области» `AE#13306` (5), список навмешей `Pathing::GetAllLoadedNavmeshes1..5` (`AE#30633`…`AE#30629`, vtable `Pathing` 2–6: интерьер **или** `exteriorBuffer`) **по коду**. Подключённый, но не текущий интерьер для них не существует.
3. **Глобальная подмена полей `TES` (класс а) годится только на главном потоке или в рамке рендера.** Читатели «текущего места» вызываются и из заданий (`Pick` через `AE#42744` ← `AE#39946` ← `ProcessActorAnimSG` `AE#41446`; анимации ячеек `Job_Cell_animations`/`Job_TES_animation`) **по коду**; одновременность с главным потоком — **предположение** (T39, пачка 3; проверит T40). Для ИИ нужен перехват по ячейке актёра (в), не подмена.
4. **Рендер держит одно «место»:** флаг `BSShaderManager::State.interior` (`+0x44`; пишет только `AE#105631`, читают всего 3 функции: `AE#107229`, `AE#106516`, `AE#106945`), центр сетки шейдеров `+0xA8…+0xBC`, слоты 8/9 корня `SSN`, `portalGraph`, корни LOD, режим неба. Все они ставятся при переходе и годятся для подмены (а) на время прохода портала.
5. **Ворота — это (г) для текущей архитектуры `TES`:** одна сетка, один `worldSpace` (47 функций + 47 через `AE#13314`), один мир Havok, одна небесная ячейка (обновляется только у текущего мира, `Main::Update+0x799`), ключ `ExteriorCellLoader` `(x,y)` без мира. Второй мир держать можно только мимо `TES` — своим списком ячеек, как `InteriorSim` держит интерьер.

## 2. Как получено

- Писатели в `AE#13316`, `AE#13315`, `AE#13317`, `AE#13288`, `AE#40466` — по `asm`: все записи в `[0x14…]` и `[reg+off]`.
- Поля `TES`: 392 функции, читающие `TES::singleton` (`AE#403450`, 690 мест), и 103 метода `TES::` (`this`); по `asm` прослежен регистр, загруженный из синглтона или `RCX` метода (скрипт в scratchpad). Метод неточен на ветвлениях и не видит `TES*`, переданный аргументом; поэтому отдельно — помощники `TES` (раздел 4). Числа ниже — нижняя граница.
- Синглтоны `Sky` (58 функций), `TESWaterSystem`, `ExteriorCellLoader`, `BGSGrassManager` — тем же скриптом; глобалы — `xrefs`.
- Разбор псевдокодом — для помощников и писателей из таблицы; 30 безымянных читателей `interiorCell` и 32 вызывающих `AE#13314` не прочитаны (пачки в `results/T42.md`).

## 5. Сценарии

### 5.1. Много интерьеров с улицы (игрок снаружи, N интерьеров подключены `InteriorSim`)

По порядку снятия:
1. **Буфер интерьеров (3):** множество удерживаемых ячеек вместо одной (б) в уже существующих перехватах `Preload`.
2. **`portalGraph` и свет:** один граф на `SSN`, а `SetPortalGraph` снимает весь свет — граф на портал (б), установка только на время прохода портала (а, R); перехват `AE#106385` уже есть.
3. **Помощники «текущего места»** (раздел 4): `Pick`, `GetCell`, `AE#13306`, `Pathing` — (в) по ячейке актёра; на J глобальной подмены не делать.
4. **Обходы `AE#13291`/`AE#13325`/`AE#13388`/`AE#13415`:** перехваты `13291`/`13325` есть — расширить на N.
5. **Уровень зоны** `AE#18199` при подключении (б).
6. **Рендер прохода портала:** `interior=1`, режим неба по ячейке, без слотов 8/9 и LOD — (а) на R вокруг прохода (T44).
7. Акустика и звук — T23.

Мир Havok, `toggleCollision`, `interiorCell` для этого сценария менять не нужно.

### 5.2. Ворота (экстерьер A ↔ экстерьер другого мира B, обе сетки живые)

1. **Загрузка B мимо `TES`:** ключ `ExteriorCellLoader` без мира (г) → синхронная загрузка ячеек B или перехват ключа; список подключённых ячеек B — свой (б).
2. **Havok:** один мир экстерьера на игру (г). Ступень 1 — B без физики («окно»); ступень 2 — второй `bhkWorld` + перехват `GetbhkWorld` и 23 функций (б+в).
3. **Небесная ячейка B:** подключить и обновлять каждый кадр (б), иначе постоянные ссылки B не живут.
4. **Помощники** `AE#13321`, `AE#13319`, `AE#13314`, `Pick`, `GetCell` для ячеек B (в).
5. **Рендер B:** слоты 8/9 и центр сетки шейдеров мира B, LOD — у `BGSTerrainManager` один набор корней (г для дали B; внутри стен не нужна), режим неба — (а) на R.
6. **Переход:** `AE#13315` делает `DetachAll` сетки (`+0x224`) и сбрасывает центры (`+0x233…+0x265`) — для бесшовного перехода (в): сменить `worldSpace` и сетку без отключения A; `SetParentCell` ровно один раз (климат, трава, регион — T15/T38).

### 5.3. Интерьер ↔ интерьер (игрок в A, портал в B)

1. **Переход:** `SetCurrentCell` отключает старый интерьер (`+0x3A1` `AE#19130(old,1)`) и сбрасывает граф (`+0x37C`) — пропуск через существующий detour `AE#13316` (в).
2. **Граф порталов** на портал (б), как в 5.1.
3. **Помощники** (`Pick`, `GetCell`, `Pathing`) для актёров B, пока текущий — A (в).
4. **Небо и свет:** режим по ячейке B на проходе портала (а).
5. Буфер интерьеров.

Самый простой из трёх: оба мира Havok свои, сетка улицы не участвует.

## 6. Итог: что делать

- **T29 (реестр порталов).** У портала — своё: удерживаемая ячейка(и) дальней стороны, граф порталов, снимок рендер-состояния для прохода (`interior`, режим неба, слоты 8/9, LOD, центр сетки шейдеров), флаг «зона инициализирована». Общие перехваты: `Preload` на множество ячеек; новые (в) — `TES::Pick`, `TES::GetCell`, `AE#13306`, `Pathing` 2–6 — решают по ячейке актёра, а не по глобалу. Подмена полей `TES` — только на M или R, не на J.
- **T21 (живая улица изнутри, второй портал на внутренней двери).** Вход в интерьер гасит улицу в пяти местах `SetCurrentCell`: `toggleCollision=0` (`+0x21`), `AE#19130(gridCell,0)` (`+0x50E`), `AE#31814` (`+0x53B`), `AE#20517` (`+0x54C`), `AE#105631(1)` (`+0x46D`); обходы `AE#13291`/`AE#13325` перестают видеть сетку. Для живой улицы — пропустить блок `+0x49C…+0x54C` в detour (в), рендер улицы из интерьера — (а) на R. Второй портал на внутренней двери — сценарий 5.3.
- **Ворота.** Объём на порядок больше: одиночки `TES` (сетка, мир, ключ загрузчика, мир Havok) обходятся только своим списком ячеек мира B. Предлагаемый путь — ступенями: сначала B как «окно» без физики и без NPC (загрузка мимо `TES`, рендер (а)), затем небесная ячейка и помощники, последним — второй `bhkWorld`.
