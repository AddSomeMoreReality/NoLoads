# T38. Карта игрока в коде — результат

Ветка: exp/T38-player-map (файлы написаны в основной папке) · Версия сборки: нет (кода нет) · Статус: исследование, шаги 1–6; шаг 7 (прогон) — с T40

## Что выяснено
Таблицы — `docs/PLAYER_MAP.md`. Всё по коду 1.6.1170 (база Ghidra), если не сказано иное.

1. **Пути к игроку:** указатель `AE#403521` (2 838 ссылок), второй указатель `AE#401069` (549, T32), хэндл `AE#403520` (111), `formID == 0x14` (2 места: `GetCurrentLocation` `AE#19812` и `SetStartingPosition` `AE#19668`, оба про `currentLocation`). Новое: виртуальный путь — `GetIsPlayerOwner` в подобъекте `ActorValueOwner` (`AE#208050` слот 8, `AE#40691`, всегда 1).
2. **Класс:** 14 vtable по RTTI. Основная `AE#208040`: 107 переопределений `Character` + 5 новых слотов (`0x12A`–`0x12E`). Во вторичных — 14 своих слотов, в том числе 4 приёмника (меню, режим меню, ввод, статистика). Сами читают `AE#403521` только 13 переопределений (`Update`, `SetParentCell`, `FinishLoadGame`, `DropObject`, `UpdateRefLight`, `GoToPrison`, `ServePrisonTime`, `PayFine`, `CheckValidTarget`, `InitiateGetUpPackage`, `AE#40687`, `AE#41258`, `AE#40740`), хэндл — 3.
3. **Где игрок для квестов — одно поле.** `currentLocation` (`+0xAD0`) пишут только `SetParentCell` (`AE#40466+0x19B`), конструктор (`AE#40411+0xE39`) и экран загрузки `AE#51929` (временно, `+0xCA` → `+0x325`). `GetCurrentLocation` для игрока возвращает это поле, а не локацию его ячейки. Подмена места (T32, Д′) его не затрагивает.
4. **`SetParentCell` игрока — не только `CLOC`:** ещё `BGSActorCellEvent` (регион, музыка, вода, HUD), климат, трава, камера (`AE#50833`), Havok, метки карты мира (`AE#40671`), граница мира. Всё глобальное, рассчитано на одну ячейку игрока.
5. **Потоки и порядок:**
   - `Main::Update` (`AE#36564`) `+0x6E` → `AE#40438`: телепорт из `queuedTargetLoc` и `PositionPlayerEvent`, в конце (`+0x839`) разбор очереди Story Manager (`AE#32484`). Главный поток. Это закрывает вопрос `LOCATION_TRIGGERS.md`, п. 2.
   - Затем `+0x2A7` → `AE#36581`: `PlayerCharacter::Update` (`+0xAD`), пересечение границы ячейки (`AE#19411` → vfunc `0x98`), сдвиг сетки `TES` по позиции игрока (`+0x201` → `AE#13288`). Главный поток.
   - Анимация (`Job_Player_animation` `AE#39055` → `AE#41371` → vfunc `0x7D`) и движение (`UpdatePlayerMovementJob` `AE#41445` → `AE#37350`) — отдельные задания `BSJobs`.
6. **Уровень обработки NPC «вокруг игрока»** — это прикрепление ячеек сетки, центр которой — позиция игрока: `AE#13288` → `AE#19063+0x2C0` → `AE#19280+0xCF` vfunc `0x91` `DoMoveToHigh` для каждой ссылки. Отдельного радиуса в этом пути нет. Порталу (5.14, пп. 1–2) достаточно держать ячейку прикреплённой: так `InteriorSim` и делает.
7. **Ещё копии места игрока:** `AE#404241`…`AE#404243` (`AE#40730`, перебор актёров в радиусе 700 — `AE#40807`, `AE#40817`, `AE#40818`); `cachedWorldSpace` `+0x630` и `exteriorPosition` `+0x638` (карта мира).
8. **Подсистемы (эвристика по именам):** актёр 637 мест, интерфейс 473, ИИ 258, формы и активация 208, ввод 165, Papyrus 164. Второй указатель (`cmp`) — только игровая логика, интерфейс его не читает.
9. **Имена базы, которые неверны:** `AE#403520` назван `gBarterMenu_TargetRefHandle` (это хэндл игрока); `AE#37350` — в базе `PlayerCharacter::AE_37350`, в docs `Character::Update`, а это движение любого актёра (зовут оба задания движения).
