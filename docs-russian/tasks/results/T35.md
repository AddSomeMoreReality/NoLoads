# T35. Интерфейс к базе Ghidra (MCP, навык, агент-читатель) — результат

Ветка: task/T35-ghidra-mcp · Версия сборки: нет (кода плагина нет) · Статус: готово к слиянию; `.mcp.json` и `.claude/` не установлены (пользователь пока не дал согласия), шаблоны — в `tools/ghidra/claude/`

## Что выяснено
- **Инструменты MCP** (`tools/ghidra/mcp_server.py`, stdio, JSON-RPC 2.0, stdlib, протоколы 2024-11-05…2025-06-18; сервер Ghidra поднимает сам):
  - `ghidra_decompile(targets, marks?, addr_prefix?, max_lines?, context?)`: функция до 150 строк — текстом, длиннее — файл и выдержки ±10 строк вокруг пометок с номерами строк файла.
  - `ghidra_asm`, `ghidra_xrefs`, `ghidra_info`, `ghidra_fieldrefs` — как в `gq.py`; `ghidra_status`.
  - `ghidra_search(name_regex | string_regex, kinds?)` — символы (без меток `AE_<id>`, 173 523) и строки (37 125), у каждого — `AE#`, число ссылок и первые места (вызовы первыми, без `.pdata`/`UNWIND_INFO`).
  - `ghidra_callgraph(target, callers|callees, depth, max_nodes)` — дерево с `AE#` и смещениями вызовов; вверх — и слоты vftable, вниз — счёт косвенных вызовов.
  - `ghidra_vtable(class, offset?)` — по RTTI MSVC (COL → смещение подобъекта, CHD → базы); слот сравнивается с первичной таблицей базы: `inherited` / `override of …` / `new in …`.
  - `ghidra_struct(name)` — раскладка типа из базы; типов NG пока нет (T36), отвечает списком похожих.
- **Проверка на известном:** `vtable PlayerCharacter` — 14 таблиц (`AE#208040`…`AE#208066`), первичная — 303 слота, база `Character`; слот `0x98` (`+0x4C0`) = `PlayerCharacter::SetParentCell` (`AE#40466`), override `Actor::SetParentCell` (`AE#37304`) — совпало с T15. `search SetParentCell$` нашёл три реализации и вызов `Actor::SetParentCell` из `AE#40466+0x236`.
- **Пул и кэш:** до 3 декомпиляторов (`CLR_GHIDRA_DECOMPILERS`), запросы идут параллельно (общая блокировка T33 снята), программа только читается. Кэш псевдокода — в памяти (400 функций) и на диске `%TEMP%\clr-ghidra\cache\<версия>-<снимок>\`; снимок — хэш `*.gbf`/`*.prp` копии (файлы `~index` меняются при каждом открытии, даже только для чтения).
- **Параллельный декомпилятор ответы не портит:** 48 функций без кэша по одной, затем в 3 и 6 потоков — все 48 файлов побайтно равны; 6 разных команд и 12 декомпиляций одновременно — все ответы равны последовательным.
- **Замеры** (тёплый сервер, если не сказано иное):

| Что | Время |
|---|---|
| Первый вызов MCP (подъём сервера) | 7,5 с (из них ~2 с — отказ `connect` к закрытому порту в Windows) |
| Накладные MCP | 20–30 мс (`info` 0,03 с) |
| `decomp` / из кэша (память, диск) | 0,1–0,7 с / 0,02–0,05 с, кэш на диске живёт после перезапуска |
| 48 функций без кэша: 1 поток / 3 / 6 | 3,5 / 1,5 / 1,4 с |
| 3 декомпиляции параллельно через MCP | 0,7 с (по одной 0,06–0,7 с) |
| `search`: первый индекс имён / строк, дальше | 6,3 / 6,0 с, затем 0,1 с |
| `vtable PlayerCharacter`, `callgraph` глубины 3 | 0,2 с, < 0,1 с |

- **Память сервера:** после запуска 0,43 ГБ, с индексами поиска 0,67 ГБ, после ~160 декомпиляций 1,2 ГБ; `decompile.exe` по 8–9 МБ.
- **Что видят субагенты — не проверено:** без `.mcp.json` (или `claude mcp add`) сервер в чатах не подключён. По устройству Claude Code: субагент без поля `tools` наследует все инструменты, включая MCP; агенты-шаблоны перечисляют `mcp__ghidra__ghidra_*` явно.

## Что изменено
- `tools/ghidra/gserver.py` — пул декомпиляторов, кэш, параллельные запросы, команды `search`, `callgraph`, `vtable`, `struct`, `status`; `PROTOCOL = 2`; ошибки ввода без трассы; `asm` помечает инструкцию, содержащую адрес.
- `tools/ghidra/gq.py` — подкоманды `search`, `callgraph`, `vtable`, `struct`; `ensure_server()` для MCP; сервер со старым протоколом перезапускается.
- `tools/ghidra/mcp_server.py` (новое) — MCP-сервер и `--selftest`. `tools/ghidra/gconfig.py` — `SERVER_DECOMPILERS`.
- `tools/ghidra/claude/` (новое) — шаблоны `mcp.json`, `skills/ghidra/SKILL.md`, агенты `re-reader` (Sonnet) и `re-reader-fast` (Haiku, разметка списков).
- `docs/GHIDRA.md` — MCP, новые команды, замеры, подключение, «Как добавить инструмент».

## Открытые вопросы
- **Подключение** (по согласию пользователя): `claude mcp add --scope local ghidra -- python tools/ghidra/mcp_server.py` в `..\CLR-GHIDRA` (только эта папка) или после слияния — копирование шаблонов в `.mcp.json` и `.claude/` (команда — `docs/GHIDRA.md`). Затем в новом чате: `/mcp`, вызов `ghidra_info AE#40466` и тот же вызов из субагента `re-reader`.
- Удалить шаблоны из `tools/ghidra/claude/` после установки или оставить их источником — решает координатор.
- `ghidra_struct` ждёт T36; `callgraph` не видит вызовы через vtable — после T36 (типы) можно разрешать слоты по типу `this`.
