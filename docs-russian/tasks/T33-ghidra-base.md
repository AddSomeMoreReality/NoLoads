## Сделать

1. **Java для Ghidra.** `JAVA_HOME_OVERRIDE=D:\Java` в `support\launch.properties` (действует только на Ghidra). Сначала спроси пользователя. Проверка — запуск `support\analyzeHeadless.bat` без аргументов.
2. **Проект** `E:\Ghidra\projects\SkyrimSE-1.6.1170`, вне репозитория. Импорт `SkyrimSE.exe` и автоанализ без окна (`analyzeHeadless … -import …`), в фоне, лог — в scratchpad. Анализ идёт часами: предупреди пользователя, что игру в это время не запускать. Настройки анализа и время — в `docs/GHIDRA.md`.
3. **Имена** (скрипт, повторяемый с нуля):
   - каждая функция по Address Library получает метку `AE_<id>`, безымянная — имя `AE_<id>`;
   - имена NG: `Класс::Метод` по `RELOCATION_ID`/`REL::ID` в исходниках NG, `VTABLE_*`, `RTTI_*`, глобальные (синглтоны; например `AE#403521` — указатель на игрока, `AE#403520` — его хэндл);
   - имена из документов проекта — комментарием с источником, имя NG они не заменяют;
   - RTTI Ghidra восстанавливает сама: сверь `PlayerCharacter` с `VTABLE_PlayerCharacter` NG;
   - отчёт: сколько функций названо из каждого источника, конфликты имён.
4. **Инструменты для исполнителей** (`tools/ghidra/`, свой код, в git):
   - псевдокод по `AE#id`, `AE#id+off` или адресу → файл в scratchpad вызывающего; несколько функций за вызов;
   - кто вызывает функцию, кто ссылается на глобал, по возможности — кто читает поле класса по смещению;
   - работа без окна. Замерь время одного вызова. Если запуск JVM и открытие программы дольше 30–60 с — долгоживущий процесс (PyGhidra) с простым клиентом или пакетные запросы;
   - проверь, можно ли два запроса одновременно (блокировка проекта). Если нельзя — очередь или копия проекта только для чтения.
5. **Проверка на известном** — псевдокод должен совпасть с выводами в документах:
   - `AE#13316` (вызовы `AE#13363`, `AE#18976`, `AE#19063` на `+0x65C`, `+0x66B`, `+0x6AA`; T20);
   - `AE#40466` (`+0x105`, `+0x11c`, `+0x154`; T15, T16);
   - `AE#19130`;
   - `AE#36629` (создание игрока: 0xBE8 байт, конструктор `AE#40411`; T31).
6. **`docs/GHIDRA.md`** (≤ 80 строк): где проект, как пересоздать, как пользоваться инструментами, правила. Правки `CLAUDE.md` и `docs/tasks/README.md` предложи в результате — вносит координатор.
7. **По желанию, вторым шагом — Creation Kit.** `CreationKit.exe` в тот же проект. Version Tracking и строки проверок с именами функций дают кандидатов имён для игры. Сначала оценка на 20 известных функциях: сколько совпало. Сборка CK новее игры, это надо учитывать.

## Правила

- **Проект Ghidra, выгрузки псевдокода и экспорт C — код Bethesda.** В git и в `docs/` их не класть: только выводы, адреса и короткие цитаты инструкций. Если что-то может попасть в дерево, добавь в `.gitignore`.
- Папку игры не менять, игру не запускать.
- Сторонние базы имён — только с понятной лицензией и источником; источник записать в `docs/GHIDRA.md`.
- 5.14, п. 6: позже понадобятся такие же проекты для SE 1.5.97 и 1.7.x (T26), если пользователь даст их `.exe`. Скрипт имён — с параметром версии и своей таблицей Address Library.
- Большие документы целиком не читай (правило 1 README задач). Кириллица в консоли Bash ломается: длинный вывод — в файл, читать через Read.
