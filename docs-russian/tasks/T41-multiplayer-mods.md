# T41. Моды мультиплеера: как они держат несколько игроков в одном мире

Этап 2, исследование без кода. Ветка `exp/T41-multiplayer`, worktree `..\CLR-T41` (без сабмодуля). Прогона нет. Веб и исходники. Базу Ghidra только читает (T35), чтобы сверить их перехваты с нашими именами.

## Зачем

T31: у движка одна личность игрока, второй `PlayerCharacter` неосуществим, спасается подмена места игрока. Моды мультиплеера решали похожую задачу — несколько «игроков» в одном мире, каждый со своими загруженными ячейками. Нужно знать, как они это сделали и где упёрлись. Это опора для T32 (рамка дальней стороны), 5.14, п. 1 (много порталов) и п. 2 (ячейки, которые держатся дольше сетки).

## Моды

Skyrim Together Reborn (TiltedEvolution), SkyMP (Skyrim Multiplayer), Keizaal (сервер на основе STR) и ранние (Skyrim Online, Skyrim Together первой версии). Для каждого — репозиторий, лицензия, версия игры, состояние.

## Вопросы

1. **Чужие игроки:** кто они в движке — NPC (`Character` с базовой формой-копией?), второй `PlayerCharacter`, что-то своё. Как получают снаряжение, анимации, характеристики.
2. **Единственность игрока:** что они делают с местами, которые знают одного игрока: ИИ и бой целятся в игрока; диалоги; квесты и Story Manager; преступления; камера; ввод. Перехватывают, подменяют или оставляют.
3. **Ячейки:**
   - каждый клиент грузит свою сетку;
   - что с чужим игроком в незагруженной ячейке или интерьере;
   - держат ли ячейки загруженными сверх сетки и как;
   - кто «владелец» ячейки (кто считает ИИ и физику NPC);
   - как переходы через двери у разных игроков.
4. **Перехваты:**
   - список функций движка, которые они перехватывают (по их исходникам: Address Library ID или сдвиги) → наши имена через базу;
   - какие совпадают с нашими (`Hooks*.cpp`), какие новы для нас.
5. **Что сломано или не решено** (баги, ограничения из документации, issues): что из этого нам грозит.
