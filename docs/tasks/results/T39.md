# T39. Карта загрузки ячеек: от двери до `kAttached` — результат

Ветка: нет, основная папка (только новые документы) · Версия сборки: нет · Статус: исследование (шаги 1–7; шаг 8 — прогон T40)

## Что выяснено
- **Все переходы игрока, кроме ходьбы, идут через `AE#40438`** (обработка `queuedTargetLoc`, `player+0x648…+0x68A` совпадает с `PLAYER_TARGET_LOC` NG). Его зовёт `Main::Update+0x6E` (M); `coc` — синхронно из `CenterOnCell_Impl+0x26A`. Очередь ставит `PlayerCharacter::AE_40442`: дверь (`HandleOpen` `AE#17926` → `AE#17924+0x1B1`, или колбэк затемнения `AE#17968`), `MoveTo_Impl+0x18B`, быстрое перемещение (`MapMenu::vf_0x4`, скрипты). `TESObjectDOOR::Activate` очередь не ставит (H1).
- **Порядок в `AE#40438`** (код + 0.7.1 `seq 713–732`, один кадр): экран загрузки `AE#13363(1,…)` `+0x4FB/+0x534/+0x642` → `kPre` `+0x55A` → `AE#40744` (`+0x6D4`) или `AE#40745` (`+0x741`) → цикл `Sleep(10)` по `ProcessLists` `+0x845` → `kPost` `+0x885` → `AE#75708(5)` `+0x8B2` → `kFinish` `+0x8DD` → закрытие `+0x952`.
- **`AE#40744`:** интерьер → `SetCurrentCell` `+0x14E`; экстерьер → `TES::AE_13315` (смена мира) `+0x155` и `TES::AE_13317` (выход в мир) `+0x16E`. `SetParentCell` (vfunc `0x98`, `CLOC`) — после подключения: `+0x19B` `AE#19411`, внутри `+0x251`. Трасса: `ActorCell enter` и `LocationChange` после `SetCurrentCell.leave`.
- **`SetCurrentCell` четвёртый аргумент не читает** (H8): в коде только `cell` и `pos`. Вход в интерьер отключает сетку (`AE#19130(cell,0)` `+0x50E`, ячейки остаются `kUnattached`, центр в `saveGridX/Y`), выключает мир Havok экстерьера (`+0xC5F9`), сбрасывает граф порталов (`+0x37C`). Выгрузка буферов и `PurgeBufferedCells` в нём — только при `bPreemptivelyUnloadCells` (`AE#358811`, у пользователя 0).
- **Длины буферов = INI** (H9 по коду): `interiorBuffer` — `uInterior Cell Buffer` (`AE#358814`), `exteriorBuffer` — `uExterior Cell Buffer` (`AE#358817`).
- **Состояния ячейки, кто пишет `+0x44`:** `AE#19112+0x181` → 2, `AE#18978+0x79` → 3, `+0xC2C` → 4, `AE#18976+0x76` → 6, `AE#19063+0x33C` → 7, `AE#19130+0x96` → 5, `+0x4BB` → 4, `AE#13721+0xC3` → 1, `AE#18981` → 0.
- **Потоки загрузки (игра, все запуски):** `CellLoaderTask::Run`+`Finish` — один IO-поток (`BSTaskManagerThread::vf_0x1` `AE#75651`), `PostProcess` — 5–6 потоков заданий (`IOManager::AE_75705` ← `AE#36565` ← `Job_IO` `AE#39084`). **`PostProcess` зовёт `AE#13434`**: буфер `TES` меняется и ячейки выгружаются (`AE#13721`) вне главного потока, замка в `AE#13434` нет.
- **Главный поток ждёт** в `IOManager::AE_75708(priority)` (`Sleep` 1/50 мс; из `SetCurrentCell`, `AE#13317`, `AE#13428`, `AE#40438`, `AE#40744`, загрузки сохранения), в цикле `AE#40438+0x845` и при закрытии экрана (`Sleep(30)`×2).
- **Один экземпляр:** `interiorCell`, одна сетка одного мира, мир Havok `AE#400440`, граф порталов, `LoadedAreaBound`, обходы «интерьер или сетка». Ключ карты `ExteriorCellLoader` — `(x,y)` без мира (`QueueCellLoad`), интерьер — `formID` в той же карте: сетки двух миров (ворота, 5.14 п. 2) столкнутся.
- **Экран загрузки обязательной работы не делает:** только UI и флаги (`AE#400336`, `LoadScreenUp`, субтитры, вибрация); под ним сетка сдвигается без ожидания очереди, ожидания IO и прогрев Havok.
- **Старые трассы совпали** с картой по вызывающим и потокам (`SetCurrentCell` 106/106 из `AE#40744`, M; `QueueCellLoad` и `SetCenter` — M; `DoorActivate` — не M). Не объяснено: `DetachAll` из `AE#13295+0x64` (загрузка сохранения) 44 раза не на M.
