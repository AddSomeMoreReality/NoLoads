# T39. Cell loading map: from the door to `kAttached` — result

Branch: none, main folder (new documents only) · Build version: none · Status: research (steps 1–7; step 8 — run T40)

## What was found
- **All player transitions except walking go through `AE#40438`** (processing `queuedTargetLoc`, `player+0x648…+0x68A` matches NG's `PLAYER_TARGET_LOC`). It is called by `Main::Update+0x6E` (M); `coc` — synchronously from `CenterOnCell_Impl+0x26A`. The queue is set by `PlayerCharacter::AE_40442`: door (`HandleOpen` `AE#17926` → `AE#17924+0x1B1`, or the door fade callback `AE#17968`), `MoveTo_Impl+0x18B`, fast travel (`MapMenu::vf_0x4`, scripts). `TESObjectDOOR::Activate` does not set the queue (H1).
- **Order inside `AE#40438`** (code + 0.7.1 `seq 713–732`, one frame): loading screen `AE#13363(1,…)` `+0x4FB/+0x534/+0x642` → `kPre` `+0x55A` → `AE#40744` (`+0x6D4`) or `AE#40745` (`+0x741`) → `Sleep(10)` loop over `ProcessLists` `+0x845` → `kPost` `+0x885` → `AE#75708(5)` `+0x8B2` → `kFinish` `+0x8DD` → close `+0x952`.
- **`AE#40744`:** interior → `SetCurrentCell` `+0x14E`; exterior → `TES::AE_13315` (world change) `+0x155` and `TES::AE_13317` (entering the world) `+0x16E`. `SetParentCell` (vfunc `0x98`, `CLOC`) — after attaching: `+0x19B` `AE#19411`, inside at `+0x251`. Trace: `ActorCell enter` and `LocationChange` after `SetCurrentCell.leave`.
- **`SetCurrentCell` does not read its fourth argument** (H8): the code touches only `cell` and `pos`. Entering an interior detaches the grid (`AE#19130(cell,0)` `+0x50E`, cells stay `kUnattached`, the center in `saveGridX/Y`), turns off the exterior's Havok world (`+0xC5F9`), resets the portal graph (`+0x37C`). Buffer unloading and `PurgeBufferedCells` in it — only under `bPreemptivelyUnloadCells` (`AE#358811`, 0 on the user's machine).
- **Buffer lengths = INI** (H9 from code): `interiorBuffer` — `uInterior Cell Buffer` (`AE#358814`), `exteriorBuffer` — `uExterior Cell Buffer` (`AE#358817`).
- **Cell states, who writes `+0x44`:** `AE#19112+0x181` → 2, `AE#18978+0x79` → 3, `+0xC2C` → 4, `AE#18976+0x76` → 6, `AE#19063+0x33C` → 7, `AE#19130+0x96` → 5, `+0x4BB` → 4, `AE#13721+0xC3` → 1, `AE#18981` → 0.
- **Load threads (game, all runs):** `CellLoaderTask::Run`+`Finish` — one IO thread (`BSTaskManagerThread::vf_0x1` `AE#75651`), `PostProcess` — 5–6 job threads (`IOManager::AE_75705` ← `AE#36565` ← `Job_IO` `AE#39084`). **`PostProcess` calls `AE#13434`**: the `TES` buffer changes and cells are unloaded (`AE#13721`) off the main thread; there is no lock in `AE#13434`.
- **The main thread waits** in `IOManager::AE_75708(priority)` (`Sleep` 1/50 ms; from `SetCurrentCell`, `AE#13317`, `AE#13428`, `AE#40438`, `AE#40744`, save loading), in the `AE#40438+0x845` loop, and when closing the screen (`Sleep(30)`×2).
- **Single instance:** `interiorCell`, one grid of one world, Havok world `AE#400440`, portal graph, `LoadedAreaBound`, "interior or grid" traversals. The `ExteriorCellLoader` map key is `(x,y)` without a world (`QueueCellLoad`), the interior is a `formID` in the same map: grids of two worlds (gates, 5.14 item 2) will collide.
- **The loading screen does no mandatory work:** only UI and flags (`AE#400336`, `LoadScreenUp`, subtitles, vibration); under it the grid shifts without waiting for the queue, IO waits, or Havok warm-up.
- **Old traces matched** the map by callers and threads (`SetCurrentCell` 106/106 from `AE#40744`, M; `QueueCellLoad` and `SetCenter` — M; `DoorActivate` — not M). Unexplained: `DetachAll` from `AE#13295+0x64` (save loading) 44 times not on M.
