# T15. Game and script reactions to player location changes — result

Branch: exp/T15-location-triggers · Build version: none (no code) · Status: research

## Findings
Details, table of 186 quests and 60 scripts — `docs/LOCATION_TRIGGERS.md`.

1. **Story Manager learns about location changes only through `CLOC`** (from the game code, high confidence). Event registration is `AE#5197`, members `Actor`/`Old Location`/`New Location`, index in `AE#380069`.
   - It is produced by a single call: `PlayerCharacter::SetParentCell` — `AE#40466`, `PlayerCharacter` vtable slot `0x98`.
   - `+0xe3`: `TESObjectCELL::GetLocation` `AE#18905`; `+0xeb`: comparison with the player's `currentLocation`; `+0x105`: event `AE#32288` (no other callers); `+0x11c`: `AddEvent_Impl` `AE#32359`.
   - `+0x154`: the same call synchronously sends `TESActorLocationChangeEvent`, i.e. Papyrus `OnLocationChange`.
   - For NPCs there is no `CLOC`; `OnLocationChange` comes from `AE#19799` (door), `AE#37313`, `AE#20541`, `AE#20542`.
2. **`AddEvent_Impl` only enqueues the event** (from the game code). Chain: `AE#40438+0x839` → `AE#32484` → `AE#32483`.
   - A quest is selected by `BGSStoryManagerQuestFinder`. In slot 3 `VisitQuest` (`AE#32430`) checks `storyManagerConditions` (`+0x110`) and calls `AE#25048(quest, event = finder+0x48)` — the start.
   - Return 0 — started, 2 — not started. Hence the +1.5/+2.2 s delay in 0.8.27.
3. **Data** (`Skyrim.esm`, `Update.esm`, 3 DLCs).
   - 186 quests in `CLOC` nodes: 172 with `ENAM=CLOC` and 14 with empty `ENAM`. Marking: ambient 26, story 148, unclear 12.
   - No other SM events about location: 31 registrations, location only in `CLOC`.
   - `OnLocationChange`: 77 scripts, 60 are bound (144 bindings), 49 of them drive quests. Another 608 `OnTriggerEnter` volumes at loading doors.
4. **Doors and gates** (from data).
   - Of 2 204 door transitions the location changes in only 922: `int→ext` 415, `ext→int` 415, `int→int` 62, `ext→ext` 30.
   - Whiterun, Markarth, Solitude gates and most Riften and Windhelm gates do **not** change the location: outside the walls it is already `WhiterunLocation` etc. `CLOC` fires earlier, while walking.
   - 55 quests never fire on any door. Many `dun*QST` fire on approach to the cave.
5. **Rule R8 without FormIDs.** Suppress the quest start on a `CLOC` produced by entering through a portal that was showing `L2`, if all of the following hold:
   - type `QUST` — None or Misc; no journal entries and objectives; no `RunOnce`;
   - neither the node conditions nor the quest conditions check quest progress (`GetStage*`, `GetQuest*`, `GetVMQuestVariable`), and there is no positive check of a specific place (`GetIsID`, `GetInCurrentLoc`, `LocationHasKeyword`…);
   - there is `GetEventData(HasKeyword, L2, K)` ("kind of place") or `GetRandomPercent` ("random encounter").
6. **R8 errors on the table.**
   - Suppresses 8 of 26 "ambient": `BardSongStarter`, `WITavern`, `WIGreeting`, `WICourier`, `WIChangeLocation01/02/08/09`.
   - Suppresses 1 of 148 story: `FreeformWinterholdCollegeA`, an assignment without a journal. It will fire on the next location change.
   - Suppresses 8 of 12 "unclear": radiant vampire attacks, `BYOHHouseStewardOffer`.
   - Misses 18 "ambient": mostly one-off vignettes with a specific place. They do not restart the song and will start on entry, as in vanilla.
   - Simpler variants ("no journal") suppress 30–68 story quests, mostly dungeons.
7. **USSEP 4.3.8a does not change the R8 result.** It overrides 60 quests and 19 nodes, adds conditions to 14 nodes. Of the eight suppressed ones it touches only `BardSongStarter`; the rule's signatures are the same.
8. **Hook points** (from the game code; in-game behavior not verified).
   - **Entry marking:** vfunc `0x98` `PlayerCharacter` (`AE#40466`) — high confidence, portable across SE and AE via NG.
   - **Quest decision:** vfunc 3 `BGSStoryManagerQuestFinder` (`VTABLE_…QuestFinder`, `RELOCATION_ID(256099, 205026)`, `AE#32430`), return 2 — medium-high confidence.
   - **Substituting `L1`** (`write_call` on `AE#40466+0x105/+0x11c`) does not work: `BardSongStarter` only looks at `L2`, and `L1 = L2` breaks `MS11Kicker`, `MGR01Trigger`, `T03PostQuest`.
   - **`OnLocationChange` must not be suppressed.** Ambient scripts there only stop themselves on exit: `WITavernPlayerScript`, `WIPlayerScript`, `RemoveSilenceMUS`.
9. **Marker triggers instead of `CLOC`** — not needed for now.
   - Marker forms require an `.esp` (5.14, item 7), and script-trigger zones in C++ still look at the player's `currentLocation`. Only the same set that R8 suppresses could fire early. Risks: double starts, a custom location model, compatibility with mods.
   - Return to them if seamless entry stops calling `SetParentCell`.

## How to verify in-game (for the next task)
1. Build with items 1–4, F8 enabled. In the Bannered Mare wait for a song, exit, enter through the portal. In the trace `story.skip BardSongStarter`, the song does not break (no `StopAllSongs` after +1.5 s).
2. Control: F8 disabled, same entry — `story.start BardSongStarter`, the song changes as in 0.8.27.
3. Enter a house through the portal: `story.skip WIGreeting`. Story quests without the rule still start: `story.start` for `CRHoldExpansion` (it has no location conditions).
4. Exit outside through the portal: `WIChangeLocation*`, `WICourier` get `story.skip` (if the chance rolled), other `story.start` as usual.
5. From the thread id in `story.start`, record which thread runs `AE#40438` (whether the tag ring needs synchronization).
