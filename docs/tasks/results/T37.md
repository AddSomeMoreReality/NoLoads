- **RTTI provides nothing:** CK has fewer classes than the game. CK-only classes are editor classes (dialogs, ATL, bnet). Forms have more virtual slots in CK (`TESObjectWEAP` 355 versus 158) — these are editor methods.
- **The main new information is enabled assertions:** a source file path in 12.8 thousand functions. This provides a file (`bsmultiboundroom.cpp`, `bsshadowlight.cpp`, `extradatalist.cpp`, …), not a function name. Approximately 110–210 new engine `Class::Method` names (for example `BSPortalGraph::AttachAlwaysRenderChild`, `BSCullingProcess::ProcessNonRecurse`, `PathingDoor::GetThisSideDoorLoc`, `Sky::UpdateWeather`).
- **Matching will be weak:** CK is built differently (incremental linking, less inlining, compiled-in checks, 10 months newer). Version Tracking correlators based on bytes and instructions will barely work; shared strings and the call graph remain.

## Decision
The brief's threshold (≥ 500 names with ≥ 80% accuracy) is most likely unattainable for names: 150–300 names are expected. The cost is several hours of analysis (138 thousand functions, 118 thousand thunks, up to 10 GB RAM) and 1–2 days for Version Tracking and verification. **Stop if the goal is names alone.**

Full analysis makes sense only for mapping "game function → source file" (estimated 2–5 thousand functions): for example, finding all code in `bsmultiboundroom.cpp`, `bsportalgraph.cpp`, and culling. If T39 or the portal needs this, it should be a separate task.
