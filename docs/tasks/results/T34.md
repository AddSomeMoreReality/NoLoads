# T34. Ghidra database: checking discrepancies and names for unnamed functions — result

Branch: task/T34-ghidra-names · Build version: none (no plugin code) · Status: ready to merge; database updated (main project, copy without types, read-only copy)

## What was found
- **References to `AE#403521`.** Byte scanning (`[rip+disp32]`, like `tools/re/riprefs.py`) found 2,954 locations. Of these, 110 are false positives: `MOV EAX,[…4F4]` is the neighboring `AE#403520`, and the scanner incorrectly guessed the immediate operand length. There are 2,844 actual locations; T31 had 2,843.
  - Before T34, Ghidra saw 2,829; the misses were 27 locations in code outside functions and 15 not disassembled.
  - Cause: leaf functions without a `.pdata` entry, referenced only by pointers in data or `lea` from code. The Create Address Tables analyzer is disabled (T33).
  - Now: 2,838 references, 6 not disassembled, 1 outside a function — code with no entry point: no `.pdata`, pointer, `lea`, or ID after `int3`.
- **Function starts.** `.pdata` has 120,080 entries, of which 27,981 are continuations (`UNW_FLAG_CHAININFO`) and 92,099 are starts. There were 67 starts without a function (all have `AE#`); now there are 0.
  - References from code outside functions fell from 11,278 to 121.
  - Phase 0 created 12,600 functions: 67 from `.pdata`, 4,280 from pointers in data, 5,146 from `lea`, 2,857 from IDs after `int3`/`ret`, 276 from names. Another 8 functions previously created on raw bytes (1-byte body, for example `AE#55563`) were recreated.
- **`FUN_`:** was 6, now 58. All have no ID in Address Library: the 6 old ones are leaf functions with one caller; the 52 new ones are 8-byte stubs from pointer tables, with no callers.
- **RTTI versus NG:** there are no more false discrepancies (previously 184 vtables and 176 RTTI); the comparison accounts for different template spellings. Actual discrepancies:
  - `0x18FCDB8`/`0x20A9110`: `FxResponseArgs<12>` in NG, `<14>` in the game;
  - `0x1A45440` and `0x1A45480`: `AutoRegisterCreator<MovementMessageFreezeDirection,…>` and `BSTDerivedCreator<…>` are swapped in NG;
  - `0x20DBFF0`, `0x20E3940`: the `BSPlatform::BSAsyncRequest<std::function<…>>` arguments differ in NG (`int` and `BSUserContentCollection const&` in the game);
  - `0x20E7A60`: `bnet::impl::FixedString<40,…>` in NG, `<2048,…>` in the game.
- **Document assertions** (`check_docs.py`): 28 assertions of the form `AE#a+0xNN` → / `<` / "from" `AE#b`.
  - 18 confirmed: 6 directly and 12 as the return address after a call.
  - 9 cannot be checked statically: this is the return address after an indirect call through a vtable (`[rax+0x8]`, `[rax+0x548]`, `[rax+0x1b8]`). Files: `FINDINGS.md:1250/1251`, `T01-digest-0.8.25.md:84–89`, `T11-npc-continuity.md:11/14`.
  - 1 does not match: **`docs/tasks/results/T11.md:15`**. `AE#41717+0x2af` is the return address after `call AE#37892`, not `AE#37877`; the chain is missing the link `AE#37892+0xa3`.
- **Function ID.** There were 66,723 analysis names; now there are 66,715.
  - Our names replaced 58 analysis names in vtable slots.
  - 11 MFC names (`CControlRectTracker`, `CMFCRibbonTabsGroup`, `CWinApp`…) are false: the game does not use MFC. These functions are `AE_<id>` again, with the old name retained as a label and comment.
  - Remaining: 66,406 `Unwind@`/`Catch@` funclets (accurate: taken from exception tables); 137 `FID_conflict` (ambiguous); 132 global CRT, 13 `std`, 5 `Concurrency`, XAudio2, 15 `MRECmpImpl` (library not identified).
- **New sources:**
  - `rtti-vslot` — our own RTTI parser, 8,558 tables: 19,990 functions named `vf_0xNN` in the namespace of the class owning the slot; 115 shared by several classes received a comment;
  - `papyrus` — 662 native functions from 44 classes (`Papyrus::ObjectReference::GetPositionX`, `…::PlaceAtMe`);
  - `console` — 736 script and 393 console commands, 1,486 handlers (`Condition::GetDistance`, `ConsoleCommand::CenterOnCell`), 9 shared ones — comment;
  - `Class::Method` strings — 87 found, 79 comments.

- **Third-party tables** (`thirdparty.py`, created at the user's request on 07.11.2026):
  - AddressLibraryDatabase (meh321): 24,524 names and 17,656 "class only". Where NG also has a name, the method matches in 4,086 of 4,560 (90%); the rest are synonyms (`IsEqual`/`IsNotEqual`, `Reset`/`ResetQuest`, `_Impl`) and IDA stubs (`j_nullsub_505_3`), which were discarded. 17,165 names won (8,817 functions, 8,348 data) and 7,051 `Class::AE_<id>`.
  - po3 CommonLibSSE `dev-1.6.1170`: 1,066 IDs, 97% agreement with NG, 16 new names (the rest are already in NG). The name matched the meh321 database for 233 IDs.
  - TiltedEvolution: 255 IDs, but these are variable names (13% agreement) — comments only.
  - **Deviation from the brief:** the brief required names from a single source to be placed only in a comment. At the user's request, they are applied as names: the source is visible in the `[clr] name from …` comment, and other nonmatching names are in `[clr] elsewhere: …`. Such names do not provide `this`, because the method may be static.
  - Table without a server: `%TEMP%\clr-ghidra\names-1.6.1170.tsv` (63,624 rows: `AE#id`, RVA, name, source).

- **Important unnamed functions:** of the 500 most-called functions, 311 are still `AE_<id>` (previously 397). Third-party tables named, for example, `AE#10854` = `NiMemoryAllocate`, `AE#69164` = `BSFixedString::Release`, `AE#68121` = `Memory::static_ctor`. Still unnamed are `AE#109588` (16,380 calls), `AE#10955`, `AE#11040`, and the `AE#681xx` family: they are absent from every source. Next — T37 (Creation Kit) or manual analysis through `re-reader-fast`.
- **Analysis of the 500 most-called functions** (07.11.2026, chosen by the user instead of full T37): 311 unnamed functions analyzed by four agents (Sonnet, `gq.py decomp`/`xrefs`); proposals with high/medium confidence and direct evidence checked by the curator, disputed ones compared against `asm`. 167 names accepted — new `reviewed` source (`tools/ghidra/reviewed_names.txt`: below curated, above NG and third-party tables, without `this`; the `[clr] reviewed:` comment contains evidence and confidence). Among the 500, **152** are now unnamed (previously 311). Examples: `AE#109588` = `operator_delete` (thunk to `MemoryManager_Free` `AE#36098`), `AE#12158` = `BSSpinLockGuard::~BSSpinLockGuard`, `AE#11040` = `GameSettingCollection::GetSingleton`, `AE#14594` = `TESForm::~TESForm`, `AE#12354` = `BaseExtraList::RemoveByType`. Remaining are empty `ret` stubs (`AE#68171`, `AE#68166`), counter releases with mask `0x3ff` (`AE#12159`, `AE#12875`), and bnet/BDK and Scaleform code without clear evidence.
- **Timing:** `collect_names.py` 5 s, repeated `apply_names.py` 30 s. Phase 0 on a fresh analysis — up to 1.5 h: creating only the 2,857 functions from IDs took 97 min because each new function rebuilds neighboring bodies. `check_base.py` 1–2 min.
