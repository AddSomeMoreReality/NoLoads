# T10. Bard song cuts off during transition — result

Branch: exp/T10-bard-song · Build version: none (code unchanged) · Status: research

## Findings
**Main point.** Nothing stops the song on exit. The scene reaches its end by itself within a few frames because the bard has no high process: after exit he is in middleHigh until the portal’s `promote` fires ~1.7 s later. Confidence is high: the game code and timing in three traces agree, but the trace does not yet record scene-line changes.
1. **A scene line without high finishes in 1–2 frames** (from game code). `BGSSceneActionDialogue` line update is `AE#24236` (vfunc 0x13). If `AIProcess::high` is null, it finishes the line through vfunc 0x11 (`AE#24235`): `+0x245 call AE#39353` (`mov rax,[rcx+10h]` … `cmp byte [rax+454h],0`) → `+0x257 call [rax+88h]`. `AE#39162` speaks the line. Without high (`+0x33 cmp qword [rcx+10h],0`), it does not take the high path `AE#39642`. If the line cannot be spoken, `AE#24236+0x149` finishes it immediately.
2. **A scene with spoken lines runs to its end** (from game code: SCEN in `Skyrim.esm`, `SF_BardSongsDrinkingSong02Sce_000D0843.psc`, `BardSongsScript.psc`). In `000D0843`, phases 0–1 are the introduction (0.25 s timers), and phases 2–7 each contain one line with no timers. Without high, six phases complete within frames, and `AE#24126+0xc9` (no phases remain) calls `AE#24140(scene, false)`. Then OnEnd `Fragment_0` calls `PlaySong(ChangeSettings=False)`: if `Bard.Is3dLoaded()`, a new random song starts; otherwise `Playing=0` and silence.
3. **The traces confirm this** (from traces):
   - 0.8.24: exit 171.42, portal 173.16, new `0006E5AE` at 173.73, old `000D0844` stopped at 174.74;
   - 0.8.24: exit 331.80, portal 333.56, new `000D0842` at 334.11, `000D0845` stopped at 335.12;
   - 0.8.25: exit 187.11, `000D0843` stopped at 188.70, portal 188.84, no new scene: the bard still has no 3D.
   The new scene starts first, and the old one stops 1.0 s later — as in natural chains inside (0.8.24: 236.62/237.62, 264.79/265.80). The old scene stops only after OnEnd, and `PlaySong` ends with `Utility.Wait(1)`. Whether there is a new song or silence is decided by the race between `PlaySong` and portal attachment.
4. **The instrumental scene survives exit, but the melody does not** (from game code and traces). Phase 3 is a line with music and a 24–33 s timer: the timer’s `IsSceneActionComplete` finishes it. This is followed by 0–20 s of timers only, which is silence by the scene’s design.
   - Melody cutoffs on exit: in 0.8.25 after exit 225.55 (the melody at 38.2 s had been playing since ~197 s) and after 269.92, `soundsCarried` is 3. In 0.8.26, `00107511` starts at 90.68, exit is 97.96, and samples 103–128 contain no long sounds.
   - Without exit, sound carrying lasts for the entire melody: in 0.8.24, 236.6–262.6 and 264.8–292.6, ~297 per 10 s, `durationMs` 30–38 s. Therefore, “sound only for the first ~20 s” is a cutoff on exit, not a short melody.
5. **`BardSongStarter` fires only on entry** (from game code and traces). Story Manager node `BardSongStarterNode` (`000D1EEB`, `CLOC` branch) sets the condition `GetEventData(HasKeyword, L2, LocTypeInn 0001CB87)`. `WhiterunBanneredMareLocation` has this keyword and `WhiterunLocation` does not.
   - 1–3 s after every entry, the old scene stops and a new one starts 1 s later: 0.8.23 — 131.5; 0.8.24 — 194.3, 297.2, 364.4; 0.8.26 — 89.7. This does not happen in 0.8.25: the fragment had been replaced there.
   - Therefore, `ARCHITECTURE.md`, line 213, is wrong: this quest is not what stops the song on exit.
6. **A control without the portal exists only for the instrumental scene** (from traces). `scene.change` has been recorded since 0.8.23, and F8 was always enabled before the first entry. The only exit without the portal is 0.8.25 at 74.39: `001069C2` survived until its natural end at 103.85. There is no control for a song with spoken lines.
7. **The scene is stopped by `AE#24140` = `BGSScene::SetActive(bool)`** (from game code).
   - With `false`, the first call sets `+0xB4`, sends the end event, and waits for OnEnd. A repeated call from `AE#24125+0x42` clears `isPlaying` (`+0xB0`).
   - Calls with `false`: Papyrus `Scene.Stop` `AE#55321` (`xor edx,edx; mov rcx,r8; jmp AE#24140`), end of phases `AE#24126+0xc9`, stop when the quest is not running `AE#24125+0x7e`.
   - Actor events arrive through `AE#24131` from Actor vfuncs 0x40, 0x41, 0x4B, 0xE5, 0x10E and Character 0xDC: death, combat, dialogue.
   - Interruptible scenes are stopped by `AE#37554` and `AE#40257`; quest stop — `AE#25016` and `AE#25047`; console — `AE#22591`. It is also called by `AE#24141`, `AE#24142`, `AE#24162`, and `AE#40092`.
8. **The script `StopBardSongOnLocChange.psc` is not attached to anything** (from game code): I checked all records in `Skyrim.esm` and `Update.esm`.
9. **The `CLOC` event is needed by 171 quests** (from game code): `ENAM=CLOC` in `Skyrim.esm`, `Update.esm`, and the three DLCs. These are `dun*QST`, `WIChangeLocation*`, `Favor*`, `CW*`, DLC1 and DLC2 quests, `WITavern`, and `DialogueWhiterunArgueScene`. Filtering the entire event would break all of them. Filtering only `BardSongStarter` requires a FormID in code and conflicts with bard mods.
10. **After entry, a melody started outside remains at the position shifted by the portal** (from traces): `listenerDistance` ≈ 27 000 (0.8.24 — 295.18; 0.8.25 — 120.49, 154.43, 258.41). It cannot be heard inside until `BardSongStarter` changes the song. The cause is the saved emitter position after `AE#68007` (hypothesis).

## Code plan
**Step 1. Diagnostic build.** It is needed: items 1–2 were inferred from code and timing; the trace does not yet show line changes.
- `src/Scenes.cpp/.h` (new file):
  - detour `AE#24140` writes `scene.stop`, only for `false`, `+0xB0=1`, `+0xB4=0`: scene, quest, phase `+0xBC`, caller and stack, as in `ActorJumps::BeforeSetPosition`. For `true` — `scene.start`;
  - vfunc `BGSSceneActionDialogue` 0x11 (`AE#24235`) writes `scene.line`: scene, `index`, phase, actor, `processLevel`, `high`, bit `0x4000` (line started), player cell, seconds after transition;
  - detour `AE#55321` writes `scene.stop.papyrus` with `stackID`.
- `src/Hooks.cpp` installs the hooks. Key `[Probe] bTraceScenes=1` — in `src/Settings.*` and `res/CellLoadResearch.ini`.
- Expected results:
  - exit: six `scene.line` records with `high=0` in less than 0.2 s, then `scene.stop` from `AE#24126+0xce`;
  - entry: `scene.stop` from Papyrus.

**Step 2. Fix** (hook only; game data unchanged).
- vfunc `BGSSceneActionDialogue` 0x13 (`AE#24236`). If the speaker has no `AIProcess::high` and its cell is held by the portal (attached or awaiting attachment), the original is not called and the line waits, but no longer than `fHoldSceneLinesSeconds=5`.
  - When high returns and the line had already started (bit `0x4000` in `+0x10`), the bit is cleared and the line plays again.
  - A `scene.hold` record (start, end, duration) goes to the trace, and a counter goes to `status`.
- Declare `Portal::HoldsCell(const RE::TESObjectCELL*)` in `src/Portal.h` and implement it in `src/PortalActors.cpp`. `InteriorSim` (`src/InteriorSim.*`) supplies the cell awaiting the portal.
- Fallback: the scene has its own pause flag `+0xB2` with reasons `+0xB5…+0xB8` (`AE#24125`, `AE#24126`). It would also stop timers, but these fields are unnamed in NG: they must be studied first.
- Do not change the song switch on entry (`BardSongStarter` → `StopAllSongs`) in T10 (item 9).

## How to verify in the game
1. Diagnostic build, F8 enabled. In the Bannered Mare, request a song with spoken lines, exit in the middle of a verse, stand by the door for 15 s, then enter.
2. Do the same with an instrumental song: exit in the middle of the melody.
3. Control: F8 disabled, repeat items 1–2. If `scene.line high=0` and `scene.stop` from `AE#24126` are the same and there is no new song, this is game behavior.
4. Build with the fix, items 1–2: after ~1.7 s, the song and melody continue outside and the current verse plays again; the trace contains `scene.hold`.
5. Subtitles: enable “Subtitles” and “General Subtitles”. In item 4, song lines are visible by the door and `subtitlesCarried` is greater than 0. The `WITavern` scene runs only 5–7 s after entry and cannot be heard outside.
6. On every entry, the song changes after 1–3 s (`BardSongStarter`): note whether this is disruptive.
