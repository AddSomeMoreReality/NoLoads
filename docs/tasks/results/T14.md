# T14. Helper mods as a dependency or a foundation — result

Branch: exp/T14-helper-mods · Build version: none (code unchanged) · Status: research

## Findings
**Main point.** No candidate is worth taking as a dependency. Engine Fixes and USSEP — compatibility only; Engine Fixes' techniques (MIT) — as ideas. It overlaps our hooks in one place, and that is harmless. But with it installed memory is different: render passes no longer come from the pool. Details — `docs/RELATED_MODS.md`, section 4.

1. **Hook overlaps between Engine Fixes and ours** (ID comparison by the `ids.py` script from the scratchpad: 213 Engine Fixes IDs against 63 code IDs and 117 `AE#`).
   - One match: `AE#106342`. We call it (`PortalLights.cpp`), and it places a `write_branch` at `+0x16` (the `nullptr` check). Harmless.
   - Our 26 detours, 5 `write_call`s, and vfuncs (`Character` 0x79/0xAD, `HighActorCuller`, `BSEffectShader*`, `GridCellArray`, `CellLoaderTask`, etc.) do not match any of its patches.
   - The T10 and T11 functions (`AE#24140`, `24235`, `24236`, `37501`, `37503`, `37618`, `37621`, `55321`), `ProcessLists` and `MoveToHigh` are untouched by any candidate.
2. **Installation order.** On 1.6.1170 `d3dx9_42.dll` calls `Initialize` before SKSE: memory, patches, fixes. Our `Hooks::Install` in `SKSE_PLUGIN_LOAD` runs after. Trampolines are separate.
3. **Engine Fixes memory** (enabled by default).
   - `bOverrideRenderPassCache`: `AE#107497`/`107498` → tbbmalloc, the `AE#107500`–`107502` pool disabled. So the words "passes from a shared pool" (`CLAUDE.md`, section 7; `PortalRender.cpp:259`) are wrong with it installed. `DrainPasses` is still needed: the lists on the property are shared.
   - Memory manager, scrap heap, Havok, Scaleform → tbbmalloc. Crashes from foreign frees (0.8.17) will manifest elsewhere. Stacks with and without it are not comparable.
   - `SafeExit` ends the process via `TerminateProcess`: the trace loses ≤ 250 ms.
4. **USSEP and the bards** (`.esp` subrecords and VMAD against `Skyrim.esm`/`Update.esm`, `.psc` from `.bsa` against `Data\Source\Scripts`).
   - `0006E53F`, `001062A7`, `000D0843`, `000D1EEB`, Saffir, Olava, Mikael are unchanged. Idolaf (`0001A689`) only gained `XLRL`.
   - `BardSongs` — plus the `TalsgarTheWanderer` property. `BardSongStarter` — the `Lurbuk` alias became Optional.
   - `BardSongsScript.pex` is replaced: the 3D, death, and disabled checks moved to the start of `PlaySong` and `Bard2PlaySong`. `StopInnMusic` silences the music only if the player is in the tavern; in vanilla — always, due to a script bug.
   - `SF_BardSongsInstrumentalFlute_0006E5AE`: `PlayIdle` only with 3D.
   - Tavern packages (innkeeper, Saffir at Heimskr's for 4 h, beds) differ per the changelog. The tavern's street door `0001A6F4` is shifted by 1 unit on X.
   - **Conclusions of T10 and T11 do not change:** the mechanism is in the engine (`AE#24236`, `AE#37503`), and the portal's bard has 3D. What changes is the comparison baseline (NPC schedules) and the street music during a song (T23).

## How to verify in-game
Two runs, the usual `feature/interior-portal` build (0.8.26), the user installs the mods through Vortex, one at a time.
1. **Run A — Engine Fixes 7.0.19 AIO** (Vortex installs `d3dx9_42.dll` into the game root by itself). Control-run scenario T02: tavern, F8, 5–6 exits and entries, look into the portal, fire in frame, one save.
2. In A verify:
   - `EngineFixes.log` shows all patches installed, our log shows `detours installed` and all `call hooks` = true;
   - no hangs or crashes, no `portal.leftovers` above 0.8.26;
   - a normal save screenshot with the portal in frame.
   Compare `digest.md` with the 0.8.26 control.
3. After A, disable Engine Fixes (Disable → Deploy) until T10 and T11 finish their runs.
4. **Run B — USSEP**, only if the user decides to install it, and after T10 and T11 are merged. Same build as T10/T11, T10 scenario: a song with lyrics, exit mid-verse.
5. In B expect the same as without USSEP. One difference: the street music does not die when the song starts (`StopInnMusic`).

## Open questions
- Keep Engine Fixes in the run environment permanently? Nearly all players have it, but it changes memory and stacks. I propose: after T10/T11, yes, and note it in HANDOFF.
- USSEP — the user's decision. Pros: most modded setups install it, bard and package bugs are fixed. Cons: a different baseline for T10/T11, a different version for 1.5.97, a data mod (5.14, item 7).
- Actor Limit Fix and Bug Fixes SSE are closed-source: what exactly they patch is unverified (Nexus returns 403).
