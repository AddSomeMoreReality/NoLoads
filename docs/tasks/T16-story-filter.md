**Решение пользователя (04.11.2026).** Две итерации.

2. Вторая — политика по тегам из T30 (`docs/tasks/T30-location-tags.md`). У каждого квеста несколько тегов (`once`, `story`, `technical`, `restarts`, `greets`, …), решение «гасить» выводится из них. ## Что известно (T15, `docs/tasks/results/T15.md`, `docs/LOCATION_TRIGGERS.md`)

- **Песню барда на входе обрывает `BardSongStarter`.** Его запускает Story Manager по `CLOC`, через +1.5 с `StopAllSongs`, через +2.2 с новая песня (прогон 0.8.27).
- **`CLOC` рождается в одном месте:** `PlayerCharacter::SetParentCell` (`AE#40466`, vtable `PlayerCharacter` слот `0x98`). Событие собирает `+0x105` (`AE#32288`), в очередь ставит `+0x11c` (`AE#32359`). Там же, на `+0x154`, синхронно уходит `OnLocationChange`.
- **Квест выбирается позже**, при разборе очереди (`AE#40438` → `AE#32484` → `AE#32483`): `BGSStoryManagerQuestFinder` vfunc 3 (`AE#32430`, `VTABLE_BGSStoryManagerQuestFinder`, `RELOCATION_ID(256099, 205026)`). Возврат 0 — квест запущен, 2 — нет. Событие — `finder+0x48`.
- **Правило R8 без FormID** гасит квест на `CLOC`, порождённом входом через портал, который уже показывал новую локацию. Квест подходит, если выполнено всё:
  - тип `QUST` — None или Misc, нет журнала и целей, нет `RunOnce`;
  - в условиях узлов и квеста нет проверок хода квестов и нет положительной проверки конкретного места;
  - есть `GetEventData(HasKeyword, L2, K)` или `GetRandomPercent`.
- **Ошибки R8 на таблице:** гасит 8 из 26 «окружений» (`BardSongStarter`, `WITavern`, `WIGreeting`, `WICourier`, `WIChangeLocation01/02/08/09`), 1 из 148 сюжетных (`FreeformWinterholdCollegeA`, сработает при следующей смене локации), 8 из 12 «неясных». В ванили под правило попадает 17 квестов. С USSEP результат тот же.
- **Не делать:** подмену старой локации в событии (ломает `MS11Kicker`, `MGR01Trigger`, `T03PostQuest`) и гашение `OnLocationChange` (49 из 60 скриптов ведут ход квестов).

## Сделать

1. **`src/StoryFilter.h/.cpp`.** Хук vfunc `0x98` `VTABLE_PlayerCharacter[0]`:
   - до оригинала спросить `Portal::ObservedEntry(oldCell, newCell)`: есть ли портал, у которого ближняя сторона `old`, дальняя `new`, и он рисовал картинку ≥ 1 с за последние `fTagSeconds`;
   - если да — метка `{oldLocation, newLocation, portal, t}` в кольцо на 8 элементов. Только FormID, без указателей на ячейки экстерьера (`CLAUDE.md`, раздел 7).
2. **Хук vfunc 3 `BGSStoryManagerQuestFinder`.** Событие `*(BGSStoryEvent**)(this + 0x48)`, индекс `CLOC` один раз по `registeredEvents[i].uniqueID`. Если локации события (`members[1]`, `members[2]`) совпадают со свежей меткой и квест в кэше R8 — вернуть 2, иначе оригинал.
3. **Кэш признаков** при `kDataLoaded` (обход узлов `CLOC`, `TESQuest::data`, цели, стадии с журналом, `storyManagerConditions`): для каждого квеста `CLOC` — маска признаков R8 (тип, журнал, цели, `RunOnce`, ход квестов, конкретное место, вид места, случайный шанс). Политика `Suppress(mask)` = R8. В лог — все квесты `CLOC` с маской и решением (в ванили R8 гасит 17).
4. **`Portal::ObservedEntry`** — функция портала, а не глобальная проверка: сейчас один портал, в T27 реестр (5.14, п. 1). Правило не делит переходы на «улица/интерьер» и работает на выходе и для любых пар ячеек (5.14, п. 2).
5. **INI `[Story]`:** `bSuppressAmbientOnPortalEntry=1` (0 — поведение игры), `fTagSeconds=5`, `bTraceStory=1`. Трасса: `story.tag`, `story.skip`, `story.start` (все запуски по `CLOC`, с id потока, EditorID и маской признаков).
6. **Вторая итерация (после T30 и согласия пользователя с политикой):** признаки T30, политика из INI (форму предложит T30), исключения по EditorID. Отдельная сборка и прогон.

## Безопасность

- В каком потоке разбирается очередь Story Manager (`AE#40438`), неизвестно: кольцо меток без блокировок (атомарные индексы), в хуке только сравнение FormID.
- `ObservedEntry` читает состояние портала: если хук vfunc 3 идёт не в главном потоке, состояние для него копировать в атомарные поля на тике `Update`.
- Новые жёсткие смещения (`finder+0x48`, раскладка `BGSStoryEvent`, `AE#40466+0x105/+0x11c/+0x154`) — в `docs/PORTABILITY.md`.
- Данные игры не меняются (`CLAUDE.md`, 5.14, п. 7): только перехват.

## Как проверить в игре

1. F8 включён. В «Гарцующей кобыле» дождаться песни, выйти, войти через портал. В трассе `story.skip BardSongStarter`, песня не обрывается (нет `StopAllSongs` через +1.5 с).
2. Контроль: F8 выключен, тот же вход — `story.start BardSongStarter`, песня меняется, как в 0.8.27.
3. Вход через портал в другой интерьер, если портал туда поставлен: `story.skip WIGreeting` и `story.start` у сюжетных квестов без правила.
4. Выход через портал наружу: на `WIChangeLocation*`, `WICourier` есть `story.skip` (если выпал шанс), остальные `story.start` на месте.
5. По id потока в `story.start` записать, где идёт `AE#40438`.

6. Первая итерация: с F8 войти в «Гарцующую кобылу» и в жилой дом — отметить, подходит ли хозяин (`WITavern`) и здоровается ли хозяин дома (`WIGreeting`). R8 их гасит, пользователь хочет их оставить: прогон покажет, что теряется.
