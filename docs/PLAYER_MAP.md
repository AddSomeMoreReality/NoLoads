# Карта игрока в коде (T38)

Статическая карта всего, что в `SkyrimSE.exe` 1.6.1170 завязано именно на игрока: класс `PlayerCharacter`, его поля, глобалы, подсистемы. Бриф — `docs/tasks/T38-player-map.md`, итог и списки для T40 — `docs/tasks/results/T38.md`. Опора — `docs/VIRTUAL_PLAYER.md` (T31) и перепись T32.

Пометки: **по коду** — база Ghidra (T35, T36), в игре не проверено; **в игре** — трасса или стек F3 из прежних прогонов; **предположение** — не проверено ничем. Подсистемы в разделе 9 разнесены по именам классов в базе и по соседним ID — это эвристика, а не доказательство.

## 1. Коротко

- **Личность игрока — четыре пути, не три:** указатель `AE#403521` (2 838 ссылок в базе), второй указатель `AE#401069` (549, почти только `cmp`, T32), хэндл `AE#403520` (111), FormID `0x14` (2 места). Пятый путь — виртуальный: `PlayerCharacter` переопределяет `ActorValueOwner::GetIsPlayerOwner` (`AE#40691`, всегда «да»).
- **Класс:** 14 vtable по RTTI. В основной (`AE#208040`, 303 слота) у игрока 112 своих слотов: 107 переопределений `Character` и 5 новых (`0x12A`–`0x12E`). Во вторичных — ещё 14 своих слотов, из них 4 — приёмники событий меню, режима меню, ввода и статистики.
- **Только 13 переопределений сами читают `AE#403521`, 3 — хэндл.** Остальные работают через `this` и блок `PLAYER_RUNTIME_DATA` (`+0x3E0`, `0x808` байт).
- **Где игрок — по коду, одним полем на всё:** `currentLocation` (`+0xAD0`) пишет только `SetParentCell` (`AE#40466+0x19B`), конструктор и экран загрузки (`AE#51929`, временно). `TESObjectREFR::GetCurrentLocation` (`AE#19812`) для `formID == 0x14` отдаёт это поле, для остальных — локацию ячейки.
- **Порядок кадра, по коду:** `MainLoop` (`AE#36550`) → `Main::Update` (`AE#36564`): `+0x6E` очередь телепорта игрока и Story Manager (`AE#40438`), `+0x2A7` обновление игрока (`AE#36581`). `AE#36581` зовёт `PlayerCharacter::Update` (vfunc `0xAD`) в главном потоке; второй вызов слота в коде — задание `UpdateActor` для актёров из списка (раздел 6). Затем пересечение границы ячейки экстерьера и сдвиг сетки `TES` по позиции игрока.
- **Анимация и движение игрока — отдельные задания пула `BSJobs`:** `Job_Player_animation` (`AE#39055`) → `AE#41371` → vfunc `0x7D`; `UpdatePlayerMovementJob` (`AE#41445`) рядом с `UpdateActorMovementJob` (`AE#41444`). Оба задания движения зовут `AE#37350`, а он сравнивает актёра с `[AE#403521]` и передаёт признак в `bhkCharacterController::TryMoveTo`.
- **Уровень обработки NPC вокруг игрока = прикреплённые ячейки:** сетка `TES` сдвигается по позиции игрока (`AE#36581+0x201` → `TES::AE_13288`), при прикреплении ячейки каждая ссылка получает vfunc `0x91` `DoMoveToHigh` (`AE#19063+0x2C0` → `AE#19280+0xCF`). Отдельного радиуса «high process» вокруг игрока в этом пути нет.
- **Одна ячейка и один мир на всё:** `SetParentCell` игрока кроме `CLOC` и `OnLocationChange` меняет климат (`Sky::SetClimate`), траву, камеру, водный мир Havok, метки карты (`AE#40671`) и рассылает `BGSActorCellEvent` (регион, музыка, вода, HUD).
- **Подсистемы:** больше всего мест — актёр (637), интерфейс (473), ИИ (258), формы и активация (208). Второй указатель читает игровая логика, интерфейс — ни разу (по эвристике раздела 9).

### 5.2 `SetParentCell` игрока (`AE#40466`, vfunc `0x98`)

По коду, по порядку: `BGSActorCellEvent` «ушёл» и «пришёл» (`AE#41034`, `+0x67`, `+0x7C`) → если локация ячейки другая: событие `CLOC` (`AE#32288`, `AddEvent_Impl`), `TESActorLocationChangeEvent` (`AE#20039`), запись `currentLocation` (`+0x19B`) → `Actor::SetParentCell` → флаг мира Havok, `MoveHavok` → `PlayerCamera::AE_50833` → `AE#13062` → `Sky::SetClimate` → `GrassManager::SetGrassEnabled` → `AE#40671` → проверка границы мира (`lastKnownGoodPosition`, `playerFlags`). Всё, кроме `Actor::SetParentCell`, глобально и рассчитано на одну ячейку игрока.

Кто зовёт vfunc `0x98` для игрока: `TESObjectCELL::AE_19411+0x251` (из `AE#36581`), `AE#40469+0x261`, `AE#40445+0x882`. Для любых ссылок, возможно и для игрока: `MoveRefToNewSpace` `AE#19799`, загрузка `AE#35717` (не проверено). Двери — через `AE#40438` (T39).
