# Почти мгновенные переходы через двери в Skyrim AE: что измерено

Этот документ — исходные данные для мода, который сокращает переход через загрузочную дверь с ~3.7 с до ~0.8 с. Все цифры измерены исследовательским SKSE-плагином CellLoadResearch (версии 0.6.0–0.7.2) в октябре 2026.

**Условия:**
- Skyrim Special Edition / Anniversary Edition, runtime **1.6.1170**, SKSE 2.2.6, CommonLibSSE-NG v13.1.0;
- место — Вайтран: дверь таверны «Гарцующая кобыла» (`WhiterunBanneredMare`), лавка Белетора (`WhiterunBelethorsGeneralGoods`), главные ворота;
- ~30 переходов в пяти запусках игры.

На SE 1.5.97 и VR ничего не проверялось.

---

## 1. Итог

| | Значения игры | С настройками из раздела 3 |
|---|---|---|
| От нажатия на дверь до картинки | **3.6–3.8 с** | **0.78–0.87 с** |
| из них загрузка ячейки | 0.25–0.36 с | 0.02–0.11 с |
| из них чёрный экран и проявление | 2.8 с | 0.1 с |

Почти всё время перехода — это не загрузка, а таймеры интерфейса и прогрев физики. Их задают обычные настройки игры (INI). Если менять их в памяти через SKSE, игра подхватывает новые значения сразу, без перезапуска.

Пользователь проверил результат визуально:
- вход почти мгновенный, чёрного экрана почти не видно;
- предметы и NPC ведут себя нормально, в том числе при первом входе в ячейку;
- осталась пауза ~0.65 с, пока «проигрывается анимация двери» (раздел 5).

## 2. Из чего состоит переход через дверь

Определение фаз через события меню `RE::MenuOpenCloseEvent` и хук `TESObjectDOOR::Activate` (vtable `TESObjectDOOR`, индекс `0x37`):

```
игрок нажал на дверь (TESObjectDOOR::Activate, вызывается НЕ в главном потоке)
  ── пауза 0.645 с (двери домов) / 0.507 с (ворота города) ──
Fader Menu open                              начало затемнения
  ── затемнение = fNormalDoorFadeSecs (0.4 с) ──
Fader Menu close → Loading Menu open → Fader Menu open
  [один кадр главного потока]
  PositionPlayerEvent kPre → загрузка ячейки → kPost
  → TES прогревает физику: fWarmStartMaxTime (4 с симуляции = 241 шаг Havok, 180–330 мс реального времени)
  → (выход наружу) ожидание очереди фоновых задач ввода-вывода, до ~60 мс
  → kFinish
Loading Menu close
  ── выдержка fMinSecondsForLoadFadeIn (1.5 с) + проявление fFadeToBlackFadeSeconds (~0.9 с) ──
Fader Menu close                             картинка видна полностью
  (+0.25–0.27 с: автосохранение «при путешествии», кадр подвисает на 87–111 мс)
```

Замер со значениями игры (0.7.1, вход/выход «Гарцующей кобылы»):

| Фаза | мс |
|---|---|
| от двери до затемнения | 644–650 |
| затемнение | 407–409 |
| экран загрузки | 253–359 |
| проявление | 2373–2376 |
| **всего** | **3688–3782** |

## 3. Настройки, которые сокращают переход

Все настройки, кроме последней, лежат в `RE::INISettingCollection` (файл `Skyrim.ini`). Имя задаётся в формате `имя:Секция`.

| Настройка | Игра | Проверено | Что делает | Эффект |
|---|---|---|---|---|
| `bPreloadLinkedInteriors:General` | 0 | **1** | Игра заранее грузит интерьеры за загрузочными дверями рядом с игроком (`CellLoaderTask` с `interior=true`, в IO-потоке) | Загрузка интерьера через дверь 420–640 мс → **18–35 мс** |
| `fWarmStartMaxTime:HAVOK` | 4 | **0** | «Тёплый старт»: после перемещения игрока `TES` синхронно прогоняет физический мир новой ячейки на столько секунд симуляции. Досрочно прогрев не заканчивается | 241 шаг, 180–330 мс → **1 шаг, 1.5–7 мс** |
| `fNormalDoorFadeSecs:General` | 0.4 | **0.05** | Длительность затемнения после нажатия на обычную загрузочную дверь | 407 мс → **50 мс** |
| `fAutoDoorFadeSecs:General` | 0.5 | 0.05 | То же для автоматических дверей | не измерялось |
| `fMinSecondsForLoadFadeIn:Interface` | 1.5 | **0** | Выдержка в темноте после экрана загрузки, до начала проявления | проявление 2.37 → 0.9 с |
| `fFadeToBlackFadeSeconds:Interface` | 1 | **0.05** | Длительность самого проявления | проявление 0.9 → **0.05 с** |
| `fTeleportDoorActivateDelayTimer` (`GameSettingCollection`, без секции) | 0.6 | 0 | — | **Не влияет:** пауза до затемнения осталась 0.645 с |

**Наборы, которые проверялись** (по 2–4 перехода в каждом, `logs/run-0.7.1`, `run-0.7.2`):

| Набор | Всего, мс | дверь→затемнение | затемнение | загрузка | проявление |
|---|---|---|---|---|---|
| значения игры | 3688–3782 | 644–650 | 407–409 | 253–359 | 2373–2376 |
| прогрев 0 + затемнение у двери 0.05 | 3130–3229 | 643–645 | 50 | 25–158 | 2377–2412 |
| + `fMinSecondsForLoadFadeIn` 0 | 1632–1693 | 644–651 | 50–51 | 30–112 | 879–908 |
| + `fFadeToBlackFadeSeconds` 0.05 | **778–872** | 643–649 | 49–51 | 23–114 | 53–73 |

Вход занимает 23–31 мс, выход наружу — 105–114 мс: на выходе остаётся ожидание очереди ввода-вывода (раздел 5).

### Побочные эффекты прогрева 0
Прогрев нужен, чтобы предметы, расставленные в редакторе, «улеглись» до того, как игрок их увидит. Проверено:
- повторные входы в таверну — без странностей;
- **первый вход** в лавку Белетора: ячейку игра предзагрузила, но физику её мира ещё ни разу не прогоняла. Предметы на полках и NPC вели себя нормально.

Не проверено:
- ячейки с трупами и регдоллами;
- висячие и подвешенные предметы;
- холодная загрузка без предзагрузки (`coc`, быстрое перемещение);
- экстерьеры с физическими объектами.

**Важно:** каждая ячейка-интерьер и каждое мировое пространство имеют свой физический мир (`bhkWorld`/`hkpWorld`). Шагает только мир того места, где игрок. Пока игрок снаружи, физика интерьеров стоит, и наоборот. Прогрев «догоняет» замороженный мир при входе, поэтому при 0 мир продолжается с того места, где замер.

## 4. Как применить в моде

### Вариант A — SKSE-плагин, значения в памяти (проверено)
Так делал CellLoadResearch: значения пишутся в объекты `RE::Setting` после загрузки данных, файлы INI не меняются.

```cpp
namespace
{
	void SetFloat(RE::INISettingCollection* a_ini, std::string_view a_name, float a_value)
	{
		if (auto* setting = a_ini->GetSetting(a_name)) {
			setting->data.f = a_value;
		}
	}

	void ApplyFastDoors()
	{
		auto* ini = RE::INISettingCollection::GetSingleton();
		if (!ini) {
			return;
		}
		if (auto* preload = ini->GetSetting("bPreloadLinkedInteriors:General")) {
			preload->data.b = true;
		}
		SetFloat(ini, "fWarmStartMaxTime:HAVOK", 0.0f);
		SetFloat(ini, "fNormalDoorFadeSecs:General", 0.05f);
		SetFloat(ini, "fAutoDoorFadeSecs:General", 0.05f);
		SetFloat(ini, "fMinSecondsForLoadFadeIn:Interface", 0.0f);
		SetFloat(ini, "fFadeToBlackFadeSeconds:Interface", 0.05f);
	}
}

// в обработчике SKSE-сообщений:
// case SKSE::MessagingInterface::kDataLoaded: ApplyFastDoors(); break;
```

- Метод `RE::INISettingCollection::GetSetting(std::string_view)` ищет по полному имени `имя:Секция`.
- У `GameSettingCollection::GetSetting` параметр `const char*`, а не `std::string_view`.
- В CellLoadResearch значения менялись прямо во время игры, по горячей клавише в главном потоке, и действовали со следующего перехода. `bPreloadLinkedInteriors` включался на первом тике игрока после загрузки данных.
- На 1.6.1170 сообщение `kDataLoaded` приходит **не в главном потоке**. Запись `float` в настройку безопасна, но если мод будет делать что-то ещё, переносите это в главный поток.
- Значения не попадают в сохранение. **Не проверено**, остаются ли они после загрузки другого сохранения или выхода в главное меню: во всех тестах их ставили уже после загрузки. Надёжнее ставить их и на `kDataLoaded`, и на `kPostLoadGame`.

### Вариант B — строки в `Skyrim.ini` (не проверено)
Настройки принадлежат коллекции `Skyrim.ini`, поэтому это должно работать так же. **Через файл не проверялось.**

```ini
[General]
bPreloadLinkedInteriors=1
fNormalDoorFadeSecs=0.05
fAutoDoorFadeSecs=0.05

[HAVOK]
fWarmStartMaxTime=0

[Interface]
fMinSecondsForLoadFadeIn=0
fFadeToBlackFadeSeconds=0.05
```

### Рекомендации к моду
- Сделать значения настраиваемыми, особенно `fWarmStartMaxTime`: например 0.25–0.5 вместо 0, если появятся «досыпающие» предметы. Цена — ~16 шагов физики на каждую 1/60 с прогрева, это 0.7–1.4 мс на шаг.
- `bPreloadLinkedInteriors=1` дешёвый: интерьеры грузятся в фоновом IO-потоке. Но в буфере интерьеров всего `uInterior Cell Buffer = 3` места, и предзагрузка вытесняет из него старые интерьеры.

## 5. Что осталось нерешённым

1. **Пауза 0.645 с (двери домов) / 0.507 с (ворота) от `Activate` до затемнения.**
   - Пользователь видит её как «анимацию двери».
   - Длительность одинакова для разных дверей одного типа.
   - `fTeleportDoorActivateDelayTimer = 0` на неё не влияет; другой настройки с таким значением в выгрузке нет.
   - Игра в это время идёт (кадры тикают); `queuedTargetLoc` игрока ещё пуст (`isValid=false` на выходе из `Activate`). Вероятно, ждёт окончания анимации или звука двери.
   - Следующий шаг: найти, кто открывает `Fader Menu` после `Activate`, и что он ждёт.
2. **Автосохранение «при путешествии».**
   - Через 0.25–0.27 с после каждого экрана загрузки кадр длится 87–111 мс: это `kSaveGame`.
   - Отключается в игре: «Настройки → Геймплей → Сохр. при путеш.» (`bSaveOnTravel`, `SkyrimPrefs.ini`).
   - Мод может предложить это игроку.
3. **Выход наружу: до ~60 мс ожидания очереди ввода-вывода.**
   - После `kPost` функция перехода `AE#40438` вызывает `AE#75708`, а тот ждёт в ядре. Этот код связан с `IOManager`/`BSTaskManager`.
   - При прогреве 4 очередь успевала опустеть за время шагов физики.
   - Какие задачи в очереди, не выяснено.
4. **Смена мирового пространства** (ворота Вайтрана): холодная загрузка 2.15–2.48 с. С настройками из раздела 3 игрок видит картинку экрана загрузки (с текстом) на это время, а затем сразу оказывается на месте. Настройки это время не сокращают: ячейки другого мира не загружены, а при выгрузке мира игра удаляет его объекты ячеек.
5. **`coc` в интерьер** каждый раз грузит его заново (не из буфера). Для перехода через дверь это не важно.

## 6. Факты о движке (AE 1.6.1170), полезные при разработке

**Порядок событий перехода** (одинаков в ~30 случаях): `Loading Menu open → kPre → ActorCell leave → загрузка → ActorCell enter → ActorLocationChange → CellFullyLoaded (если ячейка не была загружена) → kPost → kFinish → Loading Menu close`.
- Фаз `kPreUpdatePackages`/`kPostUpdatePackages` не бывает.
- Всё от `Loading Menu open` до `close` происходит **за один кадр** главного потока.

**Функции (Address Library ID для AE):**

| ID | Что это |
|---|---|
| 13316 | `TES::SetCurrentCell` — вызывается только при входе в интерьер |
| 13419 | `TES` как `BSTEventSink<PositionPlayerEvent>` (`TES+0x68`, vfunc 1). На `kPost` запускает прогрев |
| 13676 → 77921 | подготовка и цикл прогрева: шаг = `fMaxTime:HAVOK` (1/60), пока сумма < `fWarmStartMaxTime` |
| 77851 | `bhkWorld::vfunc[0x32](bhkWorld*, int)` — один шаг мира; шаг берёт из глобальных переменных |
| 61410 | `hkpWorld::stepDeltaTime(float)` |
| 40438 | функция перехода игрока; вызывает рассылку `PositionPlayerEvent` (`AE#41051`) |
| 75708 | ожидание очереди фоновых задач (рядом с `IOManager::vfunc[0x14]` = `AE#75710`) |
| 18541 | `ExteriorCellLoader::QueueCellLoad` |

**Потоки:**
- **не в главном потоке приходят:** `TESObjectDOOR::Activate`, события ввода, `TESCellFullyLoadedEvent` экстерьера, SKSE-сообщение `kDataLoaded`;
- **мутации игры** (телепорт, UI, изменение мира) делать в главном потоке, например в хуке `PlayerCharacter::Update` (vtable `PlayerCharacter`, индекс `0xAD`);
- **отложенная работа:** не ставить задачу из `SKSE::GetTaskInterface()->AddTask` повторно из неё самой — SKSE крутит очередь, пока она не опустеет, и игра виснет.

**Подводные камни:**
- Объекты ячеек экстерьера (`TESObjectCELL`) удаляются при выгрузке мирового пространства. Не храните на них указатели, храните FormID или координаты. Интерьеры — постоянные формы.
- **F5/F9 — быстрое сохранение и загрузка игры.** Не используйте их как горячие клавиши. Свободны F1–F4, F6–F8.
- `<windows.h>` (через spdlog) определяет макросы `MAX_PATH`, `min`, `max`, `CP_ACP`.

## 7. Как мерить самому
- **Фазы:** метки времени (`steady_clock`) в хуке `TESObjectDOOR::Activate` и в `BSTEventSink<MenuOpenCloseEvent>` для `Fader Menu` и `Loading Menu`. «Картинка видна» = `Fader Menu close` после `Loading Menu close`.
- **События меню:** `Fader Menu` приходит из разных потоков, `Loading Menu` — из главного.
- **Если проявления нет вообще** (например, при `fMinSecondsForLoadFadeIn=0` и коротком проявлении), к закрытию экрана загрузки `Fader Menu` может быть уже закрыт. Проверяйте `RE::UI::IsMenuOpen("Fader Menu")` при закрытии `Loading Menu`.
- **Шаги физики:** detour на `hkpWorld::stepDeltaTime` (`AE#61410`), счётчик по указателю мира.
- **Исходники и сырые данные:**
  - код: `E:\Games\Skyrim\ModCreation\My attempts\NoLoads\CellLoadResearch` (`src/Events.cpp` — фазы, `src/Overrides.cpp` — подмена настроек);
  - трассы: `logs/run-0.7.0` … `run-0.7.2`;
  - разбор: `docs/FINDINGS.md` (гипотезы H4 и H13).
